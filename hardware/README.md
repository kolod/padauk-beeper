# Beeper hardware

DipTrace project for the beeper: a 26 × 25 mm two-layer board with a CR2032 holder on
the bottom and everything else on top.

The library is generated by [generate.py](generate.py), which holds all parts, symbols,
footprints and the netlist. Edit the script and regenerate; changes made to the library in
DipTrace are overwritten.

The schematic and the PCB were laid out and routed by hand in DipTrace, so `beeper.dchxml` and
`beeper.dipxml` are the master copies and `generate.py` leaves them alone by default.
`--schematic` and `--pcb` overwrite them with the original generated layout.

```sh
python generate.py               # library only
python generate.py --schematic   # also reset the schematic (loses manual layout)
python generate.py --pcb         # also reset the PCB (loses the routing)
```

| File | Open in | Contents |
|---|---|---|
| `beeper.dchxml` | Schematic Capture | Schematic (edited in DipTrace). VDD/GND use the standard `auto_net_ports.eli` ports; signal nets connect by name (hidden wires, the net name is shown at each pin) |
| `beeper.dipxml` | PCB Layout | Placed and routed board with copper pours (edited in DipTrace) |
| `beeper_library.elixml` | Component Editor | Symbols and footprints of the project-specific parts (U1, BT1, BZ1, JP1–JP3, J1); C1, C2, R1 are custom DipTrace parts and VDD/GND come from `auto_net_ports.eli` |
| `beeper_patterns.libxml` | Pattern Editor | Standalone footprint library: every footprint the schematic uses, including the custom C/R, with 3D models (edited in DipTrace). First made by `python export_patterns.py`; `--force` recreates it and drops the DipTrace edits |

Open each file with **File ▸ Open**, choosing the DipTrace XML file type, then save it in the native
format (`.dch`, `.dip`, `.eli`).

## Circuit

| Ref | Part | Footprint | Notes |
|---|---|---|---|
| U1 | Padauk PFS154-S08 | SOIC-8 3.9 × 4.9 mm | Firmware in [../software](../software) |
| BT1 | Keystone 3034 | SMD, bottom side | CR2032 holder. The negative contact is a Ø17.8 mm pad on the PCB under the cell |
| BZ1 | Murata PKLCS1212E4001-R1 | 12 × 12 mm SMD | Piezo sounder, 4 kHz resonance |
| R1 | 330 Ω | 0603 | Limits current pulses into the piezo's capacitance and keeps it from loading PA3 during programming |
| C1 | 100 nF | 0603 | Decoupling next to U1 |
| C2 | 10 µF | 0805 | Buffer for the coin cell |
| JP1–JP3 | Solder jumper | 1.0 × 1.5 mm pads, 0.3 mm gap | Melody select. No paste, so they stay open after reflow |
| J1 | 1 × 6 header, 2.54 mm | Through-hole | In-circuit programming, can be left unpopulated |

| U1 pin | Signal | Connected to |
|---|---|---|
| 1 | VDD | BT1 +, C1, C2, J1.1 |
| 2 | PA7 | JP3 (select bit 2) |
| 3 | PA6 | JP2 (select bit 1), J1.5 |
| 4 | PA5 | JP1 (select bit 0), J1.4 |
| 5 | PA3 | R1 → BZ1, J1.2 |
| 6 | PA4 | J1.3 (programming only) |
| 7 | PA0 | not connected |
| 8 | GND | BT1 −, C1, C2, BZ1, JP1–JP3, J1.6 |

Bridging a jumper ties its pin to GND and selects bit = 1 (see the melody table in the
[main README](../README.md)).

## DipTrace XML notes

Learned from files saved by DipTrace, which the specs leave out:

- A symbol pin's `X`/`Y` is its end at the symbol body. The wire connects `Length` away, in the
  direction given by `Orientation`: `0` left, `90` up, `180` right, `270` down.
- DipTrace re-centres every symbol on the bounding box of its pins and shapes. `generate.py` does
  the same, so its wire coordinates match.
- Footprint pads are numbered from 1, and a symbol pin's `PadId` is the pad's `Id`.

## Things to check before ordering

- **Design rules and connectivity.** Run **Verification ▸ Check Design Rules** and
  **Check Net Connectivity** in PCB Layout after any change.
- **Footprints against the datasheets.** The dimensions come from the KiCad footprint library,
  which is drawn from the manufacturer drawings. Still compare them with the current datasheets
  before ordering boards:
  - [Keystone 3034](https://www.keyelco.com/product.cfm/product_id/798)
  - [Murata PKLCS1212E4001-R1](https://www.murata.com/en-us/products/productdetail?partno=PKLCS1212E4001-R1)
  - PFS154 (SOP8, 150 mil): [docs/](../docs)
- **Programming in-circuit.** PA5 and PA6 are also programming pins, and PA5 carries the
  programming voltage. Program the chip before bridging JP1/JP2, or remove the solder bridge
  first.
